# Auditoría UX — ALPACART Tienda

## Loading states
- **Loader** solo se usa como fallback de `Suspense` en el router (lazy loading de páginas)
- **Ninguna página** implementa loading states para operaciones mock (login, checkout, etc.) porque todas son síncronas
- **Skeleton** componente existe pero nunca se usa

## Error states
- **ErrorBoundary** global captura errores de render en `StoreLayout`
- **Login** tiene validación local (campos vacíos → mensaje de error)
- **Checkout/AddressForm** tiene validación local de formulario
- **No hay manejo de errores** para operaciones mock porque no hay llamadas asíncronas

## Forms
- **Login** valida que email y password no estén vacíos
- **Checkout/AddressForm** valida campos localmente
- **ProfileSettings** no persiste cambios (solo estado local)
- **Register** es placeholder — no tiene formulario
- **Ningún formulario** se comunica con backend

## Feedback visual
- **Cart badge** en StoreHeader se actualiza correctamente en tiempo real vía `cartStore.subscribe`
- **Wishlist toggle** funciona localmente (add/remove en localStorage)
- **Toast** container está en StoreLayout pero solo se activa vía `UIContext.addToast` (nunca se llama desde páginas)
- **Sin feedback visual** en operaciones mock (no hay confirmaciones, no hay spinners)

## Responsive
- StoreHeader tiene menú hamburguesa para mobile
- StoreFooter usa grid adaptable
- CategoryGrid tiene sidebar que probablemente se oculta en mobile
- StoreNavbar se renderiza completa — no se observa variante mobile
- En general el layout parece responsive pero no se ha verificado a fondo

## Navegación
- Breadcrumb solo en 4 páginas
- Sin indicación de página activa en navbar para rutas anidadas
- Sin scroll restoration
- Sin foco programático en formularios

## Accesibilidad
- StoreHeader usa `aria-label` en icon buttons
- Sin skip-to-content link
- Sin etiquetas ARIA avanzadas
- Sin manejo de foco en modales/drawers
